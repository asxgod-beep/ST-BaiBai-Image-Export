# 柏宝绘 · 图文导出

SillyTavern 第三方扩展：把**当前聊天里选定的 AI 楼层**正文与柏宝绘配图，导出成**图文混排的 Word（.docx）或 EPUB（.epub）**。

默认**只导正文**：AI 楼层里的思维链、规划、吐槽、状态块（`<konatan_planning~>`、`<tucao>`、`<current_event>`、`<progress>` 之类）会被整块剥掉，不会混进文档。

一句话：正文里怎么排，Word 里就怎么排——文字段落、列表、引用、标题，配图按 `<bbi_image>` 标签在正文中的位置插入，图下可选出图提示词；EPUB 则按同一套正文顺序生成可翻页的电子书。

> v1.4.10：AI 回复层放宽标签名识别范围，日文、西里尔字母及特殊符号标签也能进检测清单；未被识别为正文容器的自定义 `<…>` 外壳会被拆开，同时保留配图标签内部结构。v1.4.9：新增「用用户发言生成 EPUB 章节名」开关，关闭后章节只显示第 N 章；标题提取会清理任意 `<…>` 包裹标签，不只处理 advice。v1.4.8：提取用户章节标题时会先拆开 `<advice>…</advice>` 包裹，标题里不会残留 advice 标签。v1.4.7：EPUB 章节名优先取紧跟其后的用户发言，格式为 `第一章：【章节名】`；上一条不是用户回复时只写 `第一章`，章节号按本次导出顺序连续编号、不跳号。v1.4.3：点击「开始导出」后立即出现进度 HUD（收集楼层 → 读取配图 `x/y` → 打包 → 交给浏览器下载 → 完成），不再等文件生成完才提示。v1.4.2：修复手机端「第一次弹窗后，第二次点击不弹窗、必须刷新」的问题——宿主把弹窗节点移走时 `dialogOpen` 没有复位；现在会监听节点消失并自动收尾，导出进行中重复点击也会提示「还在处理」。v1.4.1：EPUB 改为**每个 AI 楼层一章**，章节名就是楼层号（第一层＝第一章、第二层＝第二章……）；v1.4.0 新增手机端整屏弹窗（安全区、`100dvh`、底部按钮常驻、44px 以上触控目标）、自定义楼层范围（如 1–10、1–5，或起止相同的单层）、Word / EPUB 二选一。v1.3.0 起，针对真实聊天里「思维链只有闭合标签、没有开标签」的写法做了专项排漏；v1.2.0 起，每次点导出会先弹出「标签确认」窗口；v1.1.0 默认只导正文；v1.0.0 会把整楼原文（含思维链）一起导出。旧版请直接替换为新版。

## 1. 它做什么 / 不做什么

**做：**

- 扫描当前聊天的全部楼层，只取 **AI 楼层**（跳过你自己的发言和带 `extra.type` 的真系统楼）；
- 按当前 swipe 的正文导出，不受历史 swipe 干扰；
- **只提取正文段**：默认剥掉思维链 / 吐槽 / 状态类标签，并以开头的 `【 时间 】` 行作为正文起点；
- 解析正文里的 `<bbi_image>…</bbi_image>`，到楼层的 `extra.bbiImage` 里找对应那张图；
- 从 ST 的静态目录读取图片二进制，压缩后**内嵌**进 docx / EPUB（不是外链，发给别人也能看）；
- 生成标题、楼层角色名、时间（可选）、图片提示词（可选）；
- 导出前可自选 **Word** 或 **EPUB**，并自选 **AI 楼层范围**（1–10、1–5，或单层）；
- 点击「开始导出」后立即显示进度 HUD：收集楼层、读取配图 `x/y`、打包、交给浏览器下载；
- 纯浏览器本地生成，不经过 ST 服务端，也不向任何地方上传内容。

**不做：**

- 不写回聊天记录、不改 `extra`、不删除任何图片；
- 不导出用户楼层、不导出系统提示；
- 不导出音频 / 视频 / 语音；
- 不导出其他聊天、不按日期批量导出（一次一份当前聊天）。

## 2. 安装

需要先装好 **柏宝绘**（本扩展只负责读它写进正文的 tag 和 `extra.bbiImage`，不依赖它的运行时代码）。

**方式 A：酒馆内直接安装（推荐）**

1. 打开酒馆的「扩展」面板 →「安装扩展」；
2. 粘贴仓库地址：`https://github.com/asxgod-beep/ST-BaiBai-Image-Export`；
3. 分支填 `main`，点安装；
4. 刷新酒馆页面，在扩展列表里勾选 **柏宝绘 · 图文导出**。

**方式 B：手动放文件夹**

1. 把整个 `ST-BaiBai-Image-Export` 文件夹放到：

   ```
   SillyTavern/public/scripts/extensions/third-party/ST-BaiBai-Image-Export/
   ```

   目录里至少要有：`manifest.json`、`index.js`、`docx.js`、`epub.js`、`style.css`。

2. 刷新酒馆页面（或重启 ST）。
3. 打开「扩展」面板，确认 `柏宝绘 · 图文导出` 已启用。
4. 入口有两个：
   - **魔杖菜单（🪄）** → `导出图文`
   - **扩展设置面板** → `柏宝绘 · 图文导出` 卡片 → `导出 Word / EPUB`
5. 高级用户还可以用斜杠命令：`/bbi-export-docx`

> 更新插件时，记得同时替换 `manifest.json`、`index.js`、`docx.js`、`epub.js` 和 `style.css`——`index.js` 会 `import './docx.js'` 和 `import './epub.js'`，少一个文件会加载失败。

## 3. 导出选项

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 导出格式 | Word | 弹窗里可选 `Word (.docx)` 或 `EPUB (.epub)`；EPUB 适合手机阅读器/电纸书 |
| 导出楼层范围 | 全部 | 只导第 N–M 个 AI 楼层；只导某一层时起止填同一个数字（如 `5` 到 `5`） |
| 只导出正文 | 开 | 自动去掉思维链、吐槽、状态块；关掉则恢复「整楼原样导出」 |
| 用户发言章节名 | 开 | 用紧跟的用户发言生成 EPUB 章节名 `第一章：【章节名】`；关闭后只显示 `第一章` |
| 正文标签（可选） | 空 | 若角色卡把正文包在某个标签里（如 `<正文>…</正文>`），填标签名即可只取内层；留空自动识别 |
| 额外排除的标签 | 空 | 自动名单没覆盖的标签，用逗号分隔补进来，例如 `konatan_planning, yuki_plan` |
| 显示楼层角色名 | 开 | 每楼顶部一行 `角色名`，并带一条浅色分隔线 |
| 显示楼层时间 | 关 | 在角色名后附带该楼的 `send_date` |
| 在图片下方附上出图提示词 | 关 | 把 tag / nl / 角色 / 负面词以灰色小字排在图片下 |
| 只导出带配图的楼层 | 关 | 勾上后，没有图可配的 AI 楼层会被跳过 |
| 压缩图片以减小文档体积 | 开 | 最长边 1600px、JPEG 质量 0.86、白底；体积约为原图 1/5–1/10 |

设置保存在 `extensionSettings.baibai_image_export`，跟随 ST 的设置一起持久化。

## 4. 正文是怎么截出来的

不同角色卡的非正文标签五花八门，所以这里不是一份写死的正则，而是四层规则叠加：

1. **正文标签**（可选，最高优先级）：填了 `正文` / `story` 之类，就直接取该标签内层；
2. **成对标签整块删除**：
   - 精确名单：`planning`、`thinking`、`cot`、`analysis`、`tucao`、`comment`、`summary`、`memory`、`status`、`progress`、`current_event`、`instruction`、`rules`、`advice`、`tool_call`、`tool_response`、`dream_scene`、`dream_big_discuss`、`details`、`disclaimer`、`history`、`admin`、`character`、`narrative_config`、`writing_style`、`writing_guidance`、`ban`、`user_input` 等；
   - 关键词包含匹配：标签名里带 `planning` / `plan` / `think` / `tucao` / `progress` / `event` / `status` / `memory` / `summary` / `note` 等任一词都会命中，所以 `<konatan_planning~>`、`<yuki_plan>`、`<xxx_tucao>` 都能识别；
   - 标签名允许 `~`、`-`、`.`、中文和数字，`</konatan_planning~>` 这种不规范的闭合也能配对；
   - `<details><summary>…</summary>…</details>` 这类折叠块按非正文整块删除，`summary` 只作为 HTML 排版标签保留。
2.5 **半截标签（只有闭合、或只有开标签）**：真实模型流式输出经常只留下 `</konatan_planning~>`，开标签丢了。这种「孤儿标签」无法按成对规则删，因此单独处理：
   - 思维链容器（`konatan_planning`、`planning`、`plan`、`think`、`thought`、`advice`、`dream_*`、`scratchpad`、`brainstorm`）的孤儿闭合标签，允许粘在文字末尾（如 `开始写！</konatan_planning~>`）；只要它在前 70% 的位置，就从开头一直切到标签结束；
   - 其他非正文标签的孤儿闭合标签，只认独占一行的写法，同样在前 70% 时切掉开头；
   - 落在正文末尾的 `</tucao>` / `</progress>` 只摘掉标签本身，不会截掉前面的正文；
   - 行首只有 `<tucao>` 而找不到闭合、位置又在 55% 之后的，从该行切到结尾。
3. **时间戳定起点**：剥完标签后，如果开头出现 `### 【 二零一零年九月二十七日 周一 十一点四十五分 】`（或 `【 … 】`）这样的整行，就从这一行开始算正文——它前面残留的任何未知标签块都会被丢掉；
   - 只看开头 800 字符，避免正文中间的 `【 场景 】` 把前半段切掉；
   - 没有时间戳的楼层，退化为「删掉开头残留的未知标签块」，从第一段正常文字开始；
4. **结尾状态块**：从末尾反复剥掉成对标签块，`<current_event>` / `<progress>` 这类即使没进名单也不会留在文末；
5. **提示词复述**：模型把 `根据前文，输出下文的大纲` 之类的提示词原样写进正文时，整行删掉；如果它出现在正文尾部、后面还跟着一段短大纲，则从这一行起整段切掉。

`<正文>`、`<story>`、`<content>`、`<text>` 这类容器会被自动解开，只留里面的内容。

**关键顺序**：先提取正文，再解析 `<bbi_image>`。思维链里经常把 tag 当例子写出来，先剥掉才能保证 `slotSeq` 和柏宝绘真正生成的槽位一一对应，不会配错图。

如果某张角色卡用了完全猜不到的标签名，把它加到「额外排除的标签」即可；这比在几十个楼层里手动删干净更省事。

### 4.1 导出前的确认弹窗

点「导出 Word / EPUB」后不会立刻生成文件，先弹出确认窗口：

1. **顶部统计**：当前聊天有多少个 AI 楼层、检测到多少种标签、有多少个 `<bbi_image>` 配图标签（配图标签始终保留，不会出现在剔除名单里）。
2. **导出格式**：选 `Word (.docx)` 或 `EPUB (.epub)`。
3. **导出楼层范围**：填「从第 __ 层 到第 __ 层」，可以用「全部」一键恢复。
   - 楼层序号按当前聊天里的 **AI 回复顺序**计算，不包含你的发言；
   - 只导某一层时，起止填同一个数字，例如 `5` 到 `5`；
   - 超出范围会提示，不会静默导出空文件。
4. **正文从哪个标签里取**：
   - `自动识别`（默认）：按时间行 + 首尾标签块规则；
   - 也可以直接选某个检测到的标签，例如 `<正文>`、`<story>`，只取该标签内层。
5. **整块不导出（勾选即删除）**：
   - 列出检测到的成对标签，显示出现次数、总字数、标签类型（含时间行 / 含配图 / 正文容器 / 疑似非正文 / 首尾块 / 其他）以及第一行预览；
   - 默认已按规则勾好：思维链、吐槽、状态块、首尾未知块会被勾选，正文候选不会被勾选；
   - 提供「全选 / 全不选」，可以逐个改。
6. **只导出正文**开关：关掉后本次导出恢复整楼原文，标签选择不生效，但格式和楼层范围仍然生效。
7. 格式、楼层范围、标签选择都**只对本次导出生效**，不会写进设置；下次导出会重新扫描、重新给默认建议，避免不同角色卡互相污染。

手机端弹窗会切成整屏卡片：顶部避开状态栏/酒馆顶栏的安全区，中间的字段区独立滚动，底部「取消 / 开始导出」常驻，不随内容滚走。

思维链内部的示例标签会被跳过，`<bbi_image>` 里的 `<slot>` / `<nl>` / `<size>` 也不会单独列出来；如果正文被包在 `<正文>` 这类容器里，容器内部的真实标签仍会被扫描到。

弹窗只列**成对出现**的标签；只有半个标签（只剩 `</konatan_planning~>` 或只剩 `<tucao>`）的楼层不会进清单，但会在导出时按 4 节的孤儿标签规则自动剔除，并在顶部统计里计入「楼层」范围。

## 5. 图片是怎么和正文对上的

导出完全复用柏宝绘的配对口径，避免「聊天里有图、导出后没有」：

1. 用与柏宝绘相同的正则切出 `<bbi_image>…</bbi_image>`，tag 序号即 `slotSeq`；
2. `promptHash` 与柏宝绘 `floor/storage.ts` 的实现**逐字一致**（cyrb53 派生，吃 tag 原文）；
3. 槽位匹配：tag 里有 `<slot>xxx</slot>` 就按 `slotId` 找，否则按 `slotSeq` 找；
4. 先找当前提示词哈希下的成品；找不到再**跨哈希找同槽位最新一张**——也就是卡片上显示的旧图（stale）；
5. `status === 'error'` 的条目、非当前 swipe 的桶一律不用。

因此：

- 手改过 tag（哈希变了）→ 仍会导出那张旧图；
- 同一个 tag 重新生成过多张 → 取该槽位最新一张；
- 图片文件被删 / 路径失效 → 该位置留一行灰色小字 `〔本张配图读取失败，已跳过〕`，其余内容照常导出。

## 6. 文档长什么样

**Word（.docx）**

- A4，四边 2.54cm 页边距；正文 11pt、1.42 倍行距；
- 顶部：`角色名 · 图文导出` + `N 个 AI 楼层 · M 张配图 · 导出时间`；
- 每楼：分隔线 + 角色名（可选时间），随后按 tag 位置插入正文与图片；
- 正文支持 `**粗体**`、`*斜体*`、`~~删除线~~`、`` `代码` ``、`# 标题`、`- 列表`、`> 引用`；
- 图片居中、等比缩放，最大宽 15cm、最大高 22cm，不跨页裁切；
- 文件名：`柏宝绘_<角色名>_图文_<YYYYMMDD-HHmm>.docx`。

**EPUB（.epub）**

- 标准 EPUB 3，`mimetype` 为首个未压缩条目，带 `META-INF/container.xml`、`content.opf`、`nav.xhtml` 和 `toc.ncx`；
- 封面页 + 每个 AI 楼层一章；开启用户发言章节名时，有紧跟用户发言的标题为 `第一章：【章节名】`，没有则只写 `第一章`，目录可跳转；
- 正文按同样的顺序渲染为 XHTML，支持标题、列表、引用、粗体/斜体/删除线/行内代码；
- 图片内嵌在 `OEBPS/images/`，按正文中的位置插入，图下保留提示词；
- 文件名：`柏宝绘_<角色名>_图文_<YYYYMMDD-HHmm>.epub`。

## 7. 已知限制

- **只导当前 swipe**：其他 swipe 的正文与配图不会进入文档；
- **只导被 tag 引用的图**：楼层里存在、但正文没有 tag 的图片不会导出（因为没有插入位置）；
- **自动识别有前提**：正文起点依赖 `【 时间 】` 行（没有就退化为「开头标签块之后」）。如果某张卡把状态块**插在正文中间**、标签名又完全不在名单里，那段会留在文中——把它加进「额外排除的标签」即可；
- **孤儿标签的位置阈值**：只有半个标签时，按「闭合标签在前 70% 切开头、开标签在后 55% 切结尾」推断；如果某张卡把思维链整段放在正文后半段，可能切不到，需要在弹窗里确认或补进「额外排除的标签」；
- 压缩开启时 **GIF 动图会变成静态首帧**（Word / EPUB 都只显示静帧）；
- webp / bmp 等 Word 不认的格式会转成 PNG（压缩开启时统一转 JPEG）；EPUB 默认也压缩成 JPEG，兼容性最好；
- EPUB 是流式排版，阅读器会按屏幕宽度重新折行，不保证和 Word 的分页逐页一致；
- 图片数量特别多（几十张以上）时，生成过程会占内存，浏览器可能卡顿几秒；进度 HUD 会停在“打包中”，不会假报进度；
- 进度 HUD 只反映生成/打包阶段；文件交给浏览器后，实际下载字节进度看浏览器自己的下载栏，扩展拿不到下载字节数；
- 手机端弹窗按 `100dvh` + 安全区适配；如果酒馆用了自定义主题把弹窗层级压住，仍可在扩展设置里关闭/重开弹窗；
- 柏宝绘若改动 `extra.bbiImage` 的存储结构，需要同步调整 `collectFloors` / `pickImageEntry`。

## 8. 开发与自测

零第三方依赖：docx 由 `docx.js` 自己拼 OOXML + store 模式 ZIP；EPUB 由 `epub.js` 复用同一个 ZIP 写入器。

```powershell
# 逻辑单测（tag 解析、hash、槽位、正文提取、文本清洗、楼层范围、EPUB 结构）
node tests/logic.test.mjs

# 生成样例 docx + epub（内含两张渐变测试图）
node tests/build-sample.mjs

# 用 python-docx 校验 Word 段落/图片/包结构
python tests/validate_docx.py tests/sample.docx

# 校验 EPUB 的 ZIP 顺序、XML 可解析、清单/spine 引用
```
